How the app is built

Seven patterns, one working app

Each pattern below solves a specific problem this app would otherwise have. The code is the real code running in the other screens — open the dispatch console and watch each one announce itself as you click.

Creational

Factoryjs/patterns/factory.js

One class owns object creation. Callers name what they want; they never learn how it is built.

Where it runs

Every vehicle tile in the picker was produced by VehicleFactory.available(), and booking calls VehicleFactory.create("SUV").

What it replaces

A chain of if (type === "BIKE") new Bike() repeated in every screen that needs a vehicle.

See it live

E-Rick and Prime were added after the app shipped: one class and one registry line each. Six tiles now, and no booking code changed.

factory.js — abstract product, concrete products, factory

          

        


        
        

          

            Behavioural
            
Strategyjs/patterns/strategy.js

            
Interchangeable algorithms behind one method. The object using them
               can be handed a different one while the program is running.

            

              Where it runs
              
The pricing dropdown. FareCalculator holds one
                 FareStrategy and asks it to calculate().

            

            

              What it replaces
              
A single calculateFare() that grows a new
                 if branch for every festival offer and never shrinks.

            

            

              See it live
              
Switch to Surge pricing. Same trip, same vehicle — the
                 receipt rebuilds itself with different line items, and no calling code changed.

            

          

          

            
strategy.js — the interface, two of the seven rules, the context

            

          

        


        
        

          

            Structural
            
Decoratorjs/patterns/decorator.js

            
A wrapper that is the same type as the thing it wraps, so wrappers
               stack — and the object underneath never finds out.

            

              Where it runs
              
The add-on checkboxes and any promo code you apply on the Offers
                 screen. Each tick wraps the fare in one more layer.

            

            

              What it replaces
              
A class per combination — five add-ons across seven pricing
                 rules is 224 subclasses — or the same if block copy-pasted into
                 all seven rules.

            

            

              See it live
              
Tick Child seat and Pet friendly on surge pricing.
                 The console prints the whole stack, and FareCalculator still thinks
                 it is holding one plain strategy.

            

          

          

            
decorator.js — the wrapper base and two add-ons

            

          

        


        
        

          

            Behavioural
            
Observerjs/patterns/observer.js

            
A subject announces that something changed; any number of subscribers
               react. The subject never learns who they are.

            

              Where it runs
              
The driver's GPS. DriverLocationPublisher emits a fix about
                 twelve times a second; six observers act on it.

            

            

              What it replaces
              
GPS code that directly calls the map, the ETA label, the fare meter,
                 the safety monitor, the logger and the push service — and breaks if any of
                 them is removed.

            

            

              See it live
              
Book a ride, then untick EtaPanelObserver while the car is
                 moving. The ETA freezes; the car keeps driving, the meter keeps counting. That is
                 the decoupling, visible.

            

          

          

            
observer.js — subject, observer, and the wiring

            

          

        


        
        

          

            Behavioural
            
Statejs/patterns/state.js

            
Each stage of the ride is its own class holding the behaviour that is
               legal at that stage. The ride delegates instead of deciding.

            

              Where it runs
              
The lifecycle panel. The label on the right of each row is the actual
                 class the ride is holding at that moment.

            

            

              What it replaces
              
The same if (status === ...) ladder copy-pasted into
                 cancel(), next(), canRate() and every other method.

            

            

              See it live
              
ArrivedState — the trip-OTP step — was added
                 last, and it cost one class. Cancel during it and you are charged Rs.50; wait for
                 Ride in progress and the button disables itself, because
                 InProgressState.canCancel is false.

            

          

          

            
state.js — the state interface, two states, and the context

            

          

        


        
        

          

            Structural
            
Adapterjs/patterns/adapter.js

            
Someone else's interface is the wrong shape and you cannot change it.
               A small class translates their call into yours.

            

              Where it runs
              
The payment picker. UPI counts in paise, the card network wants an
                 authorise-then-capture pair, the wallet throws when it is short, and cash has no
                 SDK at all.

            

            

              What it replaces
              
A switch (method) inside the payment code that has to
                 remember four argument shapes, two units and one exception.

            

            

              See it live
              
Spend your wallet down below the fare and book anyway. The console
                 shows ledger.debit() throwing and the adapter quietly falling back to
                 UPI — the gateway never knew.

            

          

          

            
adapter.js — the adaptee, the target interface, the adapter

            

          

        


        
        

          

            Structural
            
Facadejs/patterns/facade.js

            
One simple door in front of a complicated building. The button says
               bookRide() and knows nothing about what happens behind it.

            

              Where it runs
              
The Book ride button. One call fans out to twelve steps across the geo,
                 matching, pricing, decorating, tracking and payment subsystems.

            

            

              What it replaces
              
A click handler that has to know all seven subsystems and the
                 correct order to call them in.

            

            

              See it live
              
Filter the console to FACADE and book. Two lines. Then clear the
                 filter to see everything those two lines set in motion.

            

          

          

            
facade.js — the one method the interface calls

            

          

        


        
        

          

            Creational
            
Singletonjs/core/dispatchLog.js · js/core/session.js

            
Exactly one instance, shared by everything. Ask for it a hundred
               times and you get the same object back every time.

            

              Where it runs
              
Twice. DispatchLog is the console — seven files write
                 to it. SessionManager is your account, wallet, saved places and trip
                 history — nine screens read it.

            

            

              What it replaces
              
Each module quietly making its own instance, so you sign in on the
                 login screen and are still a stranger on the wallet screen.

            

            

              See it live
              
Book a ride, then open Activity and Wallet. The trip and the debit are
                 already there, because all three screens hold the same object.

            

          

          

            
dispatchLog.js — the instance guard
