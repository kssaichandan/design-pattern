How the app is built

Seven patterns and three real-world fixes. Open a card for the problem, the fix and the real code.

1

Drivers cancel on you

State

Problem 84% of riders were pushed to cancel — and paid the fee.

Fix RematchingState finds a new driver at the same fare. You pay Rs.0.

Try: Your trip › Test › Driver cancels

2

Fares you can't trust

Decorator

Problem 3–4× festival surges; claims of prices set by phone model.

Fix Two guards wrap every rule: surge capped at the legal 2×, device ignored.

Try: Pricing rule › Festival surge ×3

3

No help when a trip goes wrong

Observer

Problem No alert when a cab leaves its route or stops for long.

Fix SafetyMonitorObserver asks “Are you okay?” with one-tap SOS.

Try: Your trip › Test › Detour

Creational Factoryjs/patterns/factory.js One class owns object creation. Callers name what they want; they never learn how it is built.
Where it runs

Every row in Choose a ride was produced by VehicleFactory.available(), and booking calls VehicleFactory.create("SUV").

What it replaces

A chain of if (type === "BIKE") new Bike() repeated in every screen that needs a vehicle.

See it live

E-Rick and Prime were added after the app shipped: one class and one registry line each. The picker drew them without being edited.

factory.js — abstract product, concrete products, factory

            

          

        


        
        

          
            Behavioural
            Strategyjs/patterns/strategy.js
            Interchangeable algorithms behind one method. The object using them can be handed a
               different one while the program is running.
          
          

            

              

                Where it runs
                
The Pricing rule picker. FareCalculator holds one
                   FareStrategy and asks it to calculate().

              

              

                What it replaces
                
A single calculateFare() that grows a new if branch for every
                   festival offer and never shrinks.

              

              

                See it live
                
Switch to Surge pricing. Same trip, same vehicle — the fare breakdown
                   rebuilds with different lines, and no calling code changed.

              

            

            

              
strategy.js — the interface, two of the eight rules, the context

              

            

          

        


        
        

          
            Structural
            Decoratorjs/patterns/decorator.js
            A wrapper that is the same type as the thing it wraps, so wrappers stack — and
               the object underneath never finds out.
          
          

            

              

                Where it runs
                
Twice. The Extras and any promo code each wrap the fare in one more layer that
                   adds a line. Then two guards wrap the whole stack to keep every fare legal.

              

              

                What it replaces
                
A class per combination — five extras across eight rules is hundreds of
                   subclasses — or the same if block and the same legal check copy-pasted into every
                   rule.

              

              

                See it live
                
Pick Festival surge ×3: the rule asks for 3x and
                   SurgeCapGuard trims it to the legal 2x. Then tick Child seat — one more row,
                   and FareCalculator still thinks it holds one plain strategy.

              

            

            

              
decorator.js — an add-on, a promo code, and the two legal guards

              

            

          

        


        
        

          
            Behavioural
            Observerjs/patterns/observer.js
            A subject announces that something changed; any number of subscribers react. The
               subject never learns who they are.
          
          

            

              

                Where it runs
                
The driver's GPS. DriverLocationPublisher emits a fix about twelve times a
                   second; six observers act on it.

              

              

                What it replaces
                
GPS code that directly calls the map, the ETA label, the fare meter, the safety monitor,
                   the logger and the push service — and breaks if any of them is removed.

              

              

                See it live
                
Book a ride, then untick EtaPanelObserver while the car is moving. The ETA
                   freezes; the car keeps driving, the meter keeps counting.

              

            

            

              
observer.js — subject, observer, and the wiring

              

            

          

        


        
        

          
            Behavioural
            Statejs/patterns/state.js
            Each stage of the ride is its own class holding the behaviour that is legal at that
               stage. The ride delegates instead of deciding.
          
          

            

              

                Where it runs
                
The ride lifecycle under the map. The class under the current stage is the actual
                   object the ride is holding at that moment.

              

              

                What it replaces
                
The same if (status === ...) ladder copy-pasted into cancel(),
                   next(), canRate() and every other method.

              

              

                See it live
                
ArrivedState (the trip OTP) and RematchingState were added last,
                   one class each. Wait for Ride in progress and Cancel disables itself, because
                   InProgressState.canCancel is false.

              

            

            

              
state.js — the state interface, two states, and the context

              

            

          

        


        
        

          
            Structural
            Adapterjs/patterns/adapter.js
            Someone else's interface is the wrong shape and you cannot change it. A small class
               translates their call into yours.
          
          

            

              

                Where it runs
                
The payment picker. UPI counts in paise, the card network wants authorise-then-capture,
                   the wallet throws when it is short, and cash has no SDK at all.

              

              

                What it replaces
                
A switch (method) inside the payment code that has to remember four argument
                   shapes, two units and one exception.

              

              

                See it live
                
Spend your wallet below the fare and book anyway. The console shows
                   ledger.debit() throwing and the adapter quietly falling back to UPI — the gateway
                   never knew.

              

            

            

              
adapter.js — the adaptee, the target interface, the adapter

              

            

          

        


        
        

          
            Structural
            Facadejs/patterns/facade.js
            One simple door in front of a complicated building. The button says
               bookRide() and knows nothing about what happens behind it.
          
          

            

              

                Where it runs
                
The Book button. One call fans out to twelve steps across the geo, matching, pricing,
                   decorating, tracking and payment subsystems.

              

              

                What it replaces
                
A click handler that has to know all seven subsystems and the order to call them
                   in.

              

              

                See it live
                
Open the console, filter to FACADE and book. Two lines. Clear the filter to see
                   everything those two lines set in motion.

              

            

            

              
facade.js — the one method the interface calls

              

            

          

        


        
        

          
            Creational
            Singletonjs/core/dispatchLog.js · js/core/session.js
            Exactly one instance, shared by everything. Ask for it a hundred times and you get the
               same object back every time.
          
          

            

              

                Where it runs
                
Twice. DispatchLog is the console — every pattern writes to it.
                   SessionManager is your account, wallet, saved places and trip history — nine screens
                   read it.

              

              

                What it replaces
                
Each module quietly making its own instance, so you sign in on one screen and are still a
                   stranger on the next.

              

              

                See it live
                
Book a ride, then open Activity and Wallet. The trip and the debit are already there,
                   because all three screens hold the same object.

              

            

            

              
dispatchLog.js — the instance guard
